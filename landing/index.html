Built for real work

Not a chat wrapper.
An agent with a toolbelt.

Every turn can inspect files, run commands, use Git, call MCP tools and verify the result — inside a workspace you control.

Autonomous tool loop

The model streams a turn, calls tools, reads the results and keeps going until the task is done or the step limit is reached.

readeditshellgittest

Permissions that mean it

Deny, allow, require-approval patterns and session approvals. Plan mode is read-only at both the prompt and permission layers.

askautoplanyolo

Workspace confined

All filesystem access goes through a symlink-safe resolver. The agent cannot escape the project by inventing a path.

Two surfaces

Your desk, or your terminal.

The same controller, permissions and sessions. Pick the interface that fits the moment.

▣ Desktop app

TagCode Desktop

A chromeless local window with a conversation, animated mascot, live inspector and approval dialogs. No Electron, no extra runtime.

  • Session / MCP / Skills inspector tabs
  • Expandable tool cards with diffs
  • Searchable model picker, saved for next launch
  • Plan view and checkpoint undo
▸ Terminal UI

Ink TUI

Fast, keyboard-first and scriptable. The same agent loop with streaming output, command completion and a live status bar.

  • Mode, provider, Git branch and context in the status bar
  • Slash commands and history navigation
  • Approval, confirm and secret modals
  • Headless tgc run for CI
Under the hood

Extend it without forking it.

MCP servers, skills and plugins plug into one permission gate and one workspace boundary.

Bring your own tools

Connect local or remote MCP servers. TagCode discovers their tools, resources and prompts, then exposes them through the same approval flow as built-ins.

stdioStreamable HTTPreconnectper-server permissions
# add a server from the desktop panel or CLI
tgc mcp add filesystem -- \
  npx -y @modelcontextprotocol/server-filesystem .

tgc mcp add remote --url \
  https://example.com/mcp

Read-only means read-only

Plan mode filters tool definitions and blocks non-read permissions. Sensitive commands require approval; every decision is audited with redacted values.

workspace confinementsecret redactionaudit log
# deny wins over everything
permissions.deny:
  - "shell:rm -rf *"

# sensitive tools always ask
permissions.requireApproval:
  - "shell:git push*"

Small core, real extension points

Plugins declare permissions, register tools and slash commands, and hook into the agent lifecycle. The core stays provider-independent.

toolscommandshookspermissions
export function activate(api) {
  api.tools.register({
    name: "release_notes",
    permission: "read",
    run: async () => ({
      ok: true,
      output: "...",
    }),
  });
}
